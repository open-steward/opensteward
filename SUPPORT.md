# Getting support

OpenSteward is supported in the open, through GitHub. Pick the route that
matches what you need.

## Questions, bugs and feature requests

Open an issue: [New issue](https://github.com/open-steward/opensteward/issues/new/choose).
There is a form for each kind of request:

- **Bug report.** Something that worked, or should work, doesn't.
- **Feature or platform request.** A new capability, or a platform or adapter
  you need.
- **Question.** How to set something up, or whether OpenSteward fits your
  use case.

Search the [existing issues](https://github.com/open-steward/opensteward/issues?q=is%3Aissue)
first, since your answer may already be there. The guides in [`docs/`](./docs/README.md)
cover setup, the admin console, the API and every vertical.

### Before you paste logs or config

Issues are public. Remove anything secret or personal before you post:

- API keys, `osk_` tokens, `ADMIN_SECRET`, and anything else from `.env`
- connect-link URLs, which carry a token anyone can use
- OAuth client secrets and webhook signing secrets
- your customers' data: names, emails, invoices, orders

## Security vulnerabilities

Never open a public issue for a security problem. Report it privately through
[GitHub Security Advisories](https://github.com/open-steward/opensteward/security/advisories/new);
[`SECURITY.md`](./SECURITY.md) describes the process and the disclosure window.

## Commercial licensing and trademarks

These are private conversations, so they go by email to
**support@opensteward.dev**:

- **Commercial licensing.** Whether what you are building needs a licence, and
  what one looks like. See [`COMMERCIAL-LICENSE.md`](./COMMERCIAL-LICENSE.md).
- **Trademarks.** Permission to use the OpenSteward name or logo. See
  [`TRADEMARKS.md`](./TRADEMARKS.md).

## Attribution corrections

If [`THIRD-PARTY-NOTICES.md`](./THIRD-PARTY-NOTICES.md) gets something wrong
about your work, open an issue or email **support@opensteward.dev**.
