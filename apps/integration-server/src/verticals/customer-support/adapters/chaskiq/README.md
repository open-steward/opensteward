# Chaskiq adapter

Open-source customer communication platform (alternative to Intercom/Crisp/Drift).

GraphQL-only API. Cloud endpoint: `https://app.chaskiq.io/graphql`. Self-hosted
instances pass `extra.instanceUrl` to override.

Auth: static Bearer token (Doorkeeper OAuth2 personal access token) + `APP` header
carrying the workspace key. No OAuth redirect flow — use `credentialFields()`.

Required credentials:
- `accessToken` — OAuth2 Bearer token from account settings
- `appKey` — workspace app key (Settings → Account)
- `instanceUrl` (optional) — self-hosted base URL, e.g. `https://chat.example.com`

## AuthorType mapping

| Condition                    | canonical AuthorType |
|------------------------------|----------------------|
| `from_bot = true`            | `system`             |
| `app_user.kind === 'agent'`  | `user`               |
| default (app_user/visitor/lead/null) | `contact`    |

`from_bot` is `true` when `trigger_id` + `step_id` are both present on the server
(i.e. the part was generated by an automation workflow, not a human).

## Supported resources

| Resource       | Operations         |
|----------------|--------------------|
| Ticket         | list, get          |
| Message        | list (per ticket)  |
| Contact        | list, get          |
| User (agent)   | list               |
| Team           | list, get          |

## Not supported

- Single-agent fetch (no per-agent GraphQL query; use `listUsers`)
- Per-message fetch (conversation parts are scoped to a conversation; use `listMessages`)
- Tags as standalone resource (tag_list is embedded on conversations/contacts)
- Webhooks (Chaskiq webhook delivery is push-only with no standardised HMAC signature scheme in the public API)
- Attachment content (only attachmentCount)
- AI-suggested-reply fields

## Refused

- Attachment content (only attachmentCount)
- Voice/call recording audio + transcripts
- Contact PII beyond email + name + phone
